Frequently Asked Questions

The important security and deployment questions, answered directly.

What is WECOMMANDER?

A secure remote-computer control platform for AI clients. A native agent connects outward to a gateway, while MCP exposes approved operations to the AI client.

Do I need to open a port on my computer?

No. The controlled device initiates the connection. The machine does not need an inbound port for the agent.

Can I self-host it?

Yes. Community mode is designed around the gateway, PostgreSQL and first-party components without a required paid infrastructure dependency.

How are dangerous actions controlled?

HIGH-risk actions require short-lived, one-time approval claims bound to the exact device, action and parameters unless local policy explicitly allows otherwise.

What happens if the AI client or gateway disconnects?

The agent reconnects automatically. Persistent tasks and PTY sessions can be rediscovered while the native agent process remains alive.

Which operating systems are supported?

The native agent and install paths are built for Windows, Linux and macOS.

Does WECOMMANDER work only with one AI provider?

No. The control surface is based on MCP so the architecture is not intentionally tied to one assistant.

Where do I manage my devices?

Use the WECOMMANDER application console at /app to pair devices, inspect state, approve operations and view audit history.

Need more details?

Open the device console to inspect your workspace, connected machines and current gateway state.
